# Ярлык для запуска JupyterLab с нужным окружением и в нужной папке

## Как это работает

Ярлык для JupyterLab можно сделать в Windows, macOS и Linux: двойной щелчок запускает сервер в нужном окружении и открывает браузер сразу в рабочей папке.

Внутри ярлыка всегда небольшой скрипт из трёх шагов:

1. Активировать окружение (conda или venv).
2. Перейти в рабочую папку.
3. Запустить `jupyter lab`.

JupyterLab считает корнем ту папку, из которой его запустили, поэтому выше неё в файловом браузере подняться нельзя. Окно терминала со скриптом должно оставаться открытым, пока вы работаете: это и есть сервер.

В примерах ниже используются условные имена — замените их на свои:

| Обозначение | Что это | Пример |
| --- | --- | --- |
| `<BASE>` | папка, куда установлена conda | `C:\Users\ivan\miniconda3`, `~/miniconda3` |
| `myenv` | имя окружения | `stats2026` |
| `<FOLDER>` | рабочая папка с ноутбуками | `D:\Teaching\Statistics`, `~/Teaching/Statistics` |

## Подготовка: три значения, которые нужно узнать

До создания ярлыка выясните путь к conda, имя окружения и рабочую папку. Команды ниже выполняются в терминале, где conda уже работает: на Windows это «Anaconda Prompt» или «Miniforge Prompt», на macOS и Linux — обычный терминал.

1. **Путь к conda.** Выполните `conda info --base`. Ответ вроде `C:\Users\ivan\miniconda3` или `/Users/ivan/miniconda3` — это и есть `<BASE>`.
2. **Имя окружения.** Выполните `conda env list`. В первой колонке — имена, во второй — полные пути. Если у нужного окружения имени нет (создано через `conda create -p ...`), используйте полный путь вместо имени.
3. **Рабочая папка.** Скопируйте путь из проводника или Finder. На Windows: Shift + правая кнопка по папке → «Копировать как путь». На macOS: правая кнопка с зажатым Option → «Скопировать путь до…».

Проверьте, что JupyterLab установлен именно в этом окружении:

```
conda activate myenv
jupyter lab --version
```

Если команда не найдена, установите его: `conda install -c conda-forge jupyterlab` или `pip install jupyterlab`.

**Если используется venv, а не conda**, вместо `<BASE>` и имени окружения нужен только путь к папке окружения, обычно это `.venv` внутри проекта.

## Windows

На Windows ярлык — это файл `.bat`, который делает три шага, плюс обычный ярлык на него с иконкой.

### Шаг 1. Включите показ расширений

Проводник → «Вид» → «Показать» → «Расширения имён файлов». Без этого Блокнот незаметно сохранит файл как `JupyterLab.bat.txt`, и он не запустится.

### Шаг 2. Создайте файл .bat

1. Откройте Блокнот.
2. Вставьте текст и подставьте свои пути.

Для conda:

```
@echo off
chcp 65001 >nul
call "C:\Users\ivan\miniconda3\Scripts\activate.bat" myenv
cd /d "D:\Teaching\Statistics"
jupyter lab
pause
```

Для venv замените строку с `call` на:

```
call "D:\Teaching\Statistics\.venv\Scripts\activate.bat"
```

3. «Файл» → «Сохранить как». Тип файла — «Все файлы», кодировка — UTF-8, имя — `JupyterLab.bat`. Удобно хранить файл прямо в рабочей папке.
4. Дважды щёлкните по файлу: откроется чёрное окно с логом, затем браузер с JupyterLab.

Что делает каждая строка:

- `chcp 65001` — переключает консоль на UTF-8, чтобы работали пути с кириллицей.
- `call ...activate.bat myenv` — активирует окружение; без `call` скрипт остановится на этой строке.
- `cd /d` — переходит в папку, в том числе на другом диске.
- `pause` — не даёт окну закрыться при ошибке, чтобы её можно было прочитать.

### Шаг 3. Ярлык с иконкой на рабочем столе

1. Правая кнопка по `JupyterLab.bat` → «Показать дополнительные параметры» (только в Windows 11) → «Отправить» → «Рабочий стол (создать ярлык)».
2. Правая кнопка по ярлыку → «Свойства» → «Сменить значок» — выберите любой файл `.ico`.
3. Там же в поле «Окно» можно выбрать «Свёрнутое в значок»: окно сервера не будет мешать, но останется на панели задач.
4. Переименуйте ярлык, например «Jupyter — Статистика».

Чтобы закрепить ярлык на панели задач, допишите в начало поля «Объект» ` cmd.exe /c  ` перед путём к `.bat`. Без этого Windows не даёт закреплять bat-файлы.

### Вариант без .bat-файла

Если в пути к conda нет пробелов, можно обойтись одним ярлыком. Правая кнопка на рабочем столе → «Создать» → «Ярлык», в поле «Объект»:

```
%windir%\System32\cmd.exe /k "%USERPROFILE%\miniconda3\Scripts\activate.bat myenv && jupyter lab"
```

Затем в свойствах ярлыка в поле «Рабочая папка» укажите `<FOLDER>`. С пробелами и кириллицей в путях надёжнее вариант с `.bat`.

## macOS

На macOS ярлык — это файл `.command`: двойной щелчок открывает его в Терминале и выполняет. При желании его можно обернуть в приложение для Dock.

### Шаг 1. Создайте файл .command

1. Откройте TextEdit и переключите его в простой текст: «Формат» → «Сделать простым текстом» (⇧⌘T).
2. Вставьте текст и подставьте свои пути.

Для conda:

```
#!/bin/zsh
source "$HOME/miniconda3/etc/profile.d/conda.sh"
conda activate myenv
cd "$HOME/Teaching/Statistics"
jupyter lab
```

Для venv замените две строки с conda на:

```
source "$HOME/Teaching/Statistics/.venv/bin/activate"
```

3. Сохраните как `JupyterLab.command`. В диалоге сохранения снимите галочку «Если расширение не указано, использовать .txt».

Строка `source .../conda.sh` нужна потому, что скрипт запускается без ваших настроек из `~/.zshrc`, и команда `conda activate` иначе не будет известна. Если conda поставлена через Homebrew, `<BASE>` обычно `/opt/homebrew/Caskroom/miniforge/base` — точный путь покажет `conda info --base`.

### Шаг 2. Разрешите запуск

Откройте Терминал и выполните (путь к файлу можно не печатать, а перетащить файл в окно Терминала):

```
chmod +x ~/Teaching/Statistics/JupyterLab.command
```

Теперь двойной щелчок по файлу открывает Терминал и запускает JupyterLab.

Если файл получен от кого-то (скачан, прислан по почте), macOS может заблокировать его как файл от неустановленного разработчика. Попробуйте запустить, затем откройте «Системные настройки» → «Конфиденциальность и безопасность» и нажмите «Всё равно открыть». То же снимает команда `xattr -d com.apple.quarantine ~/Teaching/Statistics/JupyterLab.command`.

### Шаг 3. Значок в Dock

**Простой способ.** Перетащите файл `.command` в правую часть Dock, рядом с Корзиной. Щелчок по нему запускает JupyterLab.

**Как настоящее приложение.**

1. Откройте Automator → «Новый документ» → «Программа».
2. Найдите действие «Запустить shell-скрипт» и перетащите его вправо.
3. Впишите одну строку: `open "$HOME/Teaching/Statistics/JupyterLab.command"`.
4. Сохраните, например, как «Jupyter Статистика» в папку «Программы» и перетащите в Dock.
5. Чтобы сменить значок: скопируйте любую картинку (⌘C), выберите приложение в Finder → ⌘I → щёлкните по маленькому значку вверху окна → ⌘V.

### Окно Терминала после остановки

Если после остановки сервера окно остаётся висеть с надписью «Процесс завершён», настройте: Терминал → «Настройки» → «Профили» → «Оболочка» → «При выходе из оболочки» → «Закрыть, если оболочка завершилась без ошибок».

## Linux

На Linux надёжнее всего сделать два файла: shell-скрипт с командами и файл `.desktop`, который появляется в меню приложений и на рабочем столе. Писать команды прямо в `.desktop` можно, но там свои правила экранирования, и `~` и `$HOME` в нём не работают.

### Шаг 1. Shell-скрипт

Создайте в рабочей папке файл `jupyterlab.sh`:

```
#!/bin/bash
source "$HOME/miniconda3/etc/profile.d/conda.sh"
conda activate myenv
cd "$HOME/Teaching/Statistics"
jupyter lab
```

Для venv замените две строки с conda на `source "$HOME/Teaching/Statistics/.venv/bin/activate"`.

Сделайте его исполняемым и проверьте:

```
chmod +x ~/Teaching/Statistics/jupyterlab.sh
~/Teaching/Statistics/jupyterlab.sh
```

Если JupyterLab открылся — скрипт рабочий, остановите сервер (Ctrl+C) и переходите дальше.

### Шаг 2. Файл .desktop

Создайте файл `~/.local/share/applications/jupyterlab-stats.desktop`. Пути в нём пишутся полностью, без `~`:

```
[Desktop Entry]
Type=Application
Name=JupyterLab — Статистика
Comment=JupyterLab в окружении myenv
Exec=/home/ivan/Teaching/Statistics/jupyterlab.sh
Terminal=true
Icon=utilities-terminal
Categories=Development;
```

- `Terminal=true` — открывает окно терминала с логом сервера; закрытие окна останавливает Jupyter.
- `Icon` — имя значка из темы или полный путь к картинке `.png` или `.svg`.

Проверить файл на ошибки: `desktop-file-validate ~/.local/share/applications/jupyterlab-stats.desktop`.

Через несколько секунд ярлык появится в меню приложений. Если нет — выполните `update-desktop-database ~/.local/share/applications` или перезайдите в систему. Оттуда же его можно закрепить на панели («Добавить в избранное» в GNOME, «Закрепить на панели задач» в KDE).

### Шаг 3. Ярлык на рабочем столе

```
cp ~/.local/share/applications/jupyterlab-stats.desktop "$(xdg-user-dir DESKTOP)/"
chmod +x "$(xdg-user-dir DESKTOP)/jupyterlab-stats.desktop"
```

Команда `xdg-user-dir DESKTOP` сама находит папку рабочего стола, даже если она называется «Рабочий стол».

- **GNOME (Ubuntu):** правая кнопка по значку → «Разрешить запуск».
- **KDE Plasma:** при первом запуске система спросит, доверять ли файлу, — подтвердите.
- **Xfce, Cinnamon, MATE:** обычно достаточно `chmod +x`; при запросе выберите «Отметить как исполняемый».

## Другие способы

Если активация окружения в скрипте неудобна, есть варианты короче — у каждого своё ограничение.

| Способ | Команда | Ограничение |
| --- | --- | --- |
| Прямой путь к Jupyter в окружении | Windows: `<BASE>\envs\myenv\Scripts\jupyter-lab.exe`; macOS и Linux: `<BASE>/envs/myenv/bin/jupyter-lab` | На Windows без активации некоторые пакеты с DLL (numpy, scipy и др.) могут не загрузиться |
| `conda run` | `<BASE>/bin/conda run -n myenv --cwd <FOLDER> --no-capture-output jupyter lab` (на Windows `<BASE>\Scripts\conda.exe`) | Без `--no-capture-output` лог и ссылка с токеном не выводятся |
| Папка параметром | `jupyter lab --notebook-dir="<FOLDER>"` | Работает из любого места, но строка длиннее; то же, что `cd` в скрипте |
| JupyterLab Desktop | Отдельное приложение, окружение и папка выбираются в интерфейсе | Ещё одна программа; версия JupyterLab привязана к его окружению |

### Один Jupyter на все окружения

Вместо отдельного ярлыка под каждое окружение можно запускать один JupyterLab, а окружение выбирать при создании ноутбука как ядро. Для этого в каждом окружении один раз выполните:

```
conda activate myenv
pip install ipykernel
python -m ipykernel install --user --name myenv --display-name "Python (myenv)"
```

После этого в лаунчере JupyterLab появится плитка «Python (myenv)», а ярлык нужен только на папку. Альтернатива — пакет `nb_conda_kernels` в окружении, где запускается Jupyter: он сам находит все conda-окружения с установленным `ipykernel`.

## Если что-то не работает

Большинство проблем — неверный путь к conda или имя окружения. Сначала запустите скрипт из терминала вручную: так видно полный текст ошибки.

| Что происходит | Причина | Что сделать |
| --- | --- | --- |
| Окно на Windows мелькает и сразу закрывается | Ошибка в одной из строк | Проверьте, что в конце есть `pause`, или запустите `.bat` из окна `cmd` |
| «conda не является внутренней или внешней командой» / `conda: command not found` | Неверный `<BASE>`; на macOS и Linux пропущена строка `source .../conda.sh` | Сверьте путь с выводом `conda info --base` |
| `EnvironmentNameNotFound` | Опечатка в имени окружения или оно создано по пути | Сверьте с `conda env list`; при необходимости укажите полный путь к окружению |
| «jupyter не найден» после активации | JupyterLab не установлен в этом окружении | `conda install -c conda-forge jupyterlab` или `pip install jupyterlab` |
| Открылась не та папка | Нет `/d` в `cd` (Windows), путь с пробелами без кавычек, `~` в файле `.desktop` | Возьмите путь в кавычки; в `.desktop` пишите полный путь |
| Непонятные символы, ошибка в пути с кириллицей (Windows) | Кодировка консоли | Первая строка после `@echo off` — `chcp 65001 >nul`, файл сохранён в UTF-8 |
| `Permission denied` (macOS, Linux) | Файл не исполняемый | `chmod +x <файл>` |
| Ярлык на Linux открывается как текст | Не разрешён запуск | Правая кнопка → «Разрешить запуск» |
| Браузер не открылся | Не задан браузер по умолчанию или сервер стартовал медленно | Скопируйте из окна терминала ссылку вида `http://localhost:8888/lab?token=...` |
| Адрес с портом 8889 вместо 8888 | Уже запущен другой сервер Jupyter | Это нормально; список серверов — `jupyter server list` |

### Как правильно остановить сервер

- В JupyterLab: меню «File» → «Shut Down».
- В окне терминала: Ctrl+C, затем подтвердите `y` (или нажмите Ctrl+C дважды).
- Закрытие окна терминала тоже останавливает сервер, но несохранённые изменения в открытых ноутбуках при этом пропадут.
